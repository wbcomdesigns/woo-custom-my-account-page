# Security review - Custom My Account Page for WooCommerce 1.7.0

Date: 2026-10-01. Scope: full plugin (minor release), plus the diff from v1.6.7.
Method: whole-plugin read-only audit, mechanical sweep (`security-sweep.sh --baseline v1.6.7`), and runtime checks on a local WooCommerce 11.1 / WP 7.1 site (Reign and Storefront).

Verdict: no Critical or High findings. Two Medium and four Low findings, all fixed in 1.7.0.

## Findings fixed in 1.7.0

| Sev | Where | Attacker story | Fix |
|---|---|---|---|
| Medium | `includes/class-woo-custom-my-account-page-functions.php` (`manage_account_content`, `init`) | A logged-in member outside an item's "Visible to roles" list could open the URL of a restricted default WooCommerce endpoint (Orders, Downloads...) or a third-party endpoint; only the menu entry was hidden. Verified: customer opened `/my-account/downloads/` restricted to administrator and got the page. | `wcmp_restrict_endpoint_access()` on `template_redirect` (20) redirects to My Account; children inherit their group's roles. Verified after: customer redirected, admin still allowed, group child blocked. |
| Medium | `public/class-woo-custom-my-account-page-public.php` (`wcmp_add_avatar`, `wcmp_print_avatar_form_ajax`) | With "Member avatar upload" off, any customer could still fetch the form nonce and upload images; every upload left the previous attachment and its square copies on disk (unbounded media growth). | Both handlers return early when the setting is off; `wcmp_delete_user_avatar()` removes attachment, square copies and registry entry on replace and reset. Verified: form endpoint returns empty when off; replace leaves exactly one attachment. |
| Low | `admin/class-woo-custom-my-account-page-admin.php` (endpoints save) + `functions.php` (`wcmp_settings_data`) | A tampered options.php POST (manage_options) storing an unknown `type` made a dynamic method call fatal on every request, including wp-admin. | Type allowlist on save; `method_exists` fallback on read. |
| Low | same save callback | Endpoint array keys and the order JSON were stored unsanitized (used as query vars, DOM ids, CSS classes). All outputs were escaped, so no XSS was found. | Keys `sanitize_key`; order JSON rebuilt from sanitized `id`/`type`/`children`. |
| Low | `wcmp_add_field_ajax` | Gate was `manage_woocommerce` while the screen and options.php require `manage_options`; generic nonce action `ajax_nonce`. No data was persisted by the AJAX, so no impact. | `manage_options` and nonce action `wcmp_add_field`. Runtime: customer and shop_manager blocked, administrator allowed. |
| Low | `wcmp_print_avatar_form_ajax` | Deprecated `is_ajax()`. | `wp_doing_ajax()`. |

## Scanner-visible but safe

- `files-superglobal` (2, `public/class-woo-custom-my-account-page-public.php`): avatar upload reads `$_FILES` only after nonce + logged-in + setting checks; type is checked with `wp_check_filetype_and_ext()` against a JPEG/PNG/GIF/WebP allowlist (no SVG), size capped at 2 MB, stored via `media_handle_upload()`. Runtime: a `.php` file is rejected with a notice.
- `no-abspath-guard` (3): `blocks/my-account/editor.asset.php` only returns an array (no output, no side effects); the other two files carry their guard below the sweep's 40-line window. Same count as v1.6.7.
- Endpoint content: `do_shortcode( wp_kses_post( wpautop() ) )` at render for everyone; only `manage_options` can author it (same trust as post content).
- Style CSS: `sanitize_hex_color` on save and output, fixed selectors.
- Link items: `esc_url_raw` on save, `esc_url` on output; `target=_blank` gets `rel="noopener noreferrer"`.
- Default-endpoint redirect: slug must exist in settings, `wp_safe_redirect` to `wc_get_endpoint_url` (no open redirect).
- SQL: one `$wpdb` query in `uninstall.php`, prepared with `esc_like`.

## Authorisation matrix (G2)

No REST routes. One admin AJAX action (`wcmp_add_field`): customer BLOCKED, shop_manager BLOCKED, administrator ALLOWED (handler dispatched in-process with a valid nonce). Avatar upload/reset act on the current user only. Role-restricted endpoint URL: customer redirected, administrator allowed.

## Mechanical sweep delta

`security-sweep.sh --baseline v1.6.7`: no CRITICAL; HIGH 2 / MEDIUM 3 identical to v1.6.7.
